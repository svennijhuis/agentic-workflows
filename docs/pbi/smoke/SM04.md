## Goal
Runner gets an Entra ID (Azure AD) access token through GitHub OIDC, no client secret stored anywhere.
## DoD
- `azure/login` with client-id, tenant-id from environment vars (not secrets values in files)
- `az account get-access-token --resource <api app id uri>` then `::add-mask::`
- federated credential subject limited to `repo:svennijhuis/<api repo>:environment:tst` and `:acc`
- app role `smoke` only; no prd subject
- check: workflow has no `client-secret`, token never echoed
## Steps
1. doc the auth step in smoke/README.md
2. auth step in smoke-run.yml
3. check-smoke-auth.sh: grep bans client-secret, echo of token, prd subject
## Technical design
- Components and files: .github/workflows/smoke-run.yml, scripts/check-smoke-auth.sh, smoke/README.md
- Module boundary: the auth step gives one masked access token from the vars AZURE_CLIENT_ID, AZURE_TENANT_ID, SMOKE_API_SCOPE; the OIDC federated exchange sits behind it
- Interfaces: vars per environment: AZURE_CLIENT_ID, AZURE_TENANT_ID, SMOKE_API_SCOPE (names only; Sven sets values)
- Sequence:
  ```mermaid
  sequenceDiagram
    participant S as smoke-run job
    participant GH as GitHub OIDC
    participant AAD as Entra ID
    participant API as API
    S->>GH: request id token (env=tst)
    GH-->>S: OIDC JWT
    S->>AAD: federated exchange
    AAD-->>S: access token role=smoke
    S->>API: Bearer token (masked)
  ```
- Failure modes: no federated cred or wrong subject: AADSTS error, job fails with step named, no retry loop
- Security: no client secret, least privilege role, tst/acc subjects only, token masked, no Azure apply by bots
- Observability: log shows aud and role claims only, never the token
- Cost: 0
- Rollback: Sven deletes the federated credential; revert
