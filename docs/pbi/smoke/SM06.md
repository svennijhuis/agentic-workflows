- proof: a failed run posts one comment with the failing scenario ids and marks the deployment failed
- door: two-way
block: B3   depends: SM03

- feedback: room

- kind: script (deterministic)
- Source: PA8 (no D row; Sven, Development Agentic Workflows room, 2026-10-25 17:48 and 17:50 (post-deploy smoke on tst/acc, Azure AD JWT)) https://github.com/svennijhuis/agentic-workflows/pull/5

## Goal
Everyone sees the smoke result where the change lives; a failure is loud.
## DoD
- pass: job summary + one PR or release comment (edit in place, no spam)
- fail: deployment status set failure + comment with scenario id, expected vs got (bodies truncated, no tokens, no personal data)
- fail opens or updates one issue labeled smoke-fail (M05 path, dedupe by env+feature)
## Steps
1. report step in smoke-run.yml (gh api, GITHUB_TOKEN, issues write)
2. redaction filter for bodies
3. fixture run with stub fail
## Technical design
- Components and files: .github/workflows/smoke-run.yml, scripts/smoke-report.sh
- Module boundary: input `smoke-result.json`, output one comment and at most one issue; redaction and dedupe sit behind it
- Interfaces: input smoke-result.json; output one comment, one issue max
- Sequence:
  ```mermaid
  flowchart LR
    R[smoke-result.json] --> P{all pass?}
    P -->|yes| C1[edit comment PASS]
    P -->|no| C2[comment FAIL + ids]
    C2 --> I[open or update smoke-fail issue]
    C2 --> D[deployment status failure]
  ```
- Failure modes: gh api error: job still fails red, summary keeps result
- Security: GITHUB_TOKEN scoped to issues and deployments write; redact bodies
- Observability: issue per env+feature
- Cost: 0
- Rollback: remove report step
