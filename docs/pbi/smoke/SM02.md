## Goal
While a feature is built, the agent turns the PBI acceptance criteria into new smoke scenarios that ship in the same PR.
## DoD
- workflow `smoke-writer.md` reads the PBI brief (S4) and the diff, writes only under `smoke/<feature>/`
- one scenario per acceptance criterion that touches an endpoint; skips with a reason line otherwise
- output passes check-smoke.sh; Tester and Reviewer review it like code
- safe-outputs: one commit or PR comment, nothing else
## Steps
1. workflow md + safe-outputs allowlist in POL01
2. prompt: behavior not procedure, read-only repo except smoke/
3. dry run on one past feature PBI
## Technical design
- Components and files: .github/workflows/smoke-writer.md, policies/POL01.yml (path allowlist), docs/pbi/smoke/SM02.md
- Module boundary: input PBI id and PR number, output one commit under `smoke/<feature>/` or one comment; the acceptance criteria to scenarios prompt sits behind it
- Interfaces: input: PBI id, PR number; output: commit under smoke/<feature>/ or comment; exit 0/1/2 (PA5)
- Sequence:
  ```mermaid
  sequenceDiagram
    participant B as Builder PR
    participant W as smoke-writer (dispatch)
    participant C as check-smoke.sh
    B->>W: PBI id + diff
    W->>W: AC to scenarios
    W->>C: scenarios.yml
    C-->>W: 0 or 1
    W->>B: commit smoke/feature/
  ```
- Failure modes: no endpoint in AC: comment with skip reason; check fails: exit 1, max 1 retry, then 2 needs-human
- Security: no network to tst/acc from the writer, no secrets, write path limited to smoke/
- Observability: run id + scenario count in PR comment
- Cost: AIC per run, needs Sven yes before first real run
- Rollback: delete workflow file, revert
