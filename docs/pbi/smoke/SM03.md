## Goal
When the release Action finishes on tst or acc, a plain workflow waits for the deployment, calls the API with the scenarios and reports.
## DoD
- `.github/workflows/smoke-run.yml` on `deployment_status` (state success, env tst|acc) plus workflow_dispatch
- waits on health endpoint (max 10 min, 15 s poll) before scenarios
- runs only scenarios for that env; prd refused at job level
- exit 0 all pass, 1 any fail
- uses GitHub environment tst/acc for base URL and OIDC (SM04)
## Steps
1. runner script `scripts/smoke-run.sh` (curl + jq)
2. workflow with env guard
3. good/bad fixtures against a local stub server in verify
## Technical design
- Components and files: .github/workflows/smoke-run.yml, scripts/smoke-run.sh, tests/stub-api/, scripts/verify.sh
- Module boundary: `scripts/smoke-run.sh` takes env, sha and SMOKE_BASE_URL and exits 0/1 with a table; health polling, auth and expect matching sit behind it
- Interfaces: input: env, sha, base URL var SMOKE_BASE_URL per environment; output: table + exit 0/1
- Sequence:
  ```mermaid
  sequenceDiagram
    participant R as Release Action
    participant GH as GitHub deployment_status
    participant S as smoke-run.yml
    participant API as API tst/acc
    R->>GH: success env=tst
    GH->>S: trigger
    S->>API: GET /health (poll)
    API-->>S: 200
    S->>API: scenarios with JWT
    API-->>S: status + body
    S->>S: compare expect, exit 0/1
  ```
- Failure modes: health never ready: fail with timeout named; 5xx: fail with scenario id; prd env: refuse
- Security: permissions: id-token write, contents read only; token from SM04, masked; no write scenario without test_data_only
- Observability: job summary table, artifact smoke-result.json (no tokens)
- Cost: 0 AIC, Actions minutes only
- Rollback: disable workflow, revert
